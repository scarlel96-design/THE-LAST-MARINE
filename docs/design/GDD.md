# 전체 설계도 V1.0 — 작업용 기준선 정리

사용자가 채팅으로 제공한 전체 설계도 V1.0을 정리했다. 원문 전체를 재전사한 문서는 아니다.
수치와 날짜는 원문과 동일한 기획 목표다. Astra 승인을 의미하지 않는다.

## 비전과 제작 원칙

평범한 연합군 해병이 침공에서 생존한다. 그는 베스퍼 VII에서 장비를 확보하고 시설을 복구한다.
그는 작전 성과를 인정받아 분대를 통솔한다. 마지막에는 부대의 생존을 책임지는 장교가 된다.
실제 전장 행동으로 사건의 원인과 결과를 보여준다. 플레이어의 조작권을 유지한다.
전술적 이유를 가진 유한한 전투를 배치한다. 장비와 스킬의 효과를 전투로 확인한다.
안정성과 원작 정합성을 우선한다. 미검증 기능을 필수 구현으로 확정하지 않는다.

## 캠페인

|미션|제목|크기 목표|시간 목표|변화|
|---|---|---|---|---|
|M01|마지막 생존자|192×192|60~90분|기지 붕괴 → 단독 생존|
|M02|고립된 전선|224×224|90~120분|보급 → 복구 → 거점 방어|
|M03|한 사람의 전쟁|256×256|100~140분|게릴라 → 군락 공격 → 구조 신호|
|M04|귀환한 망령|256×256|90~130분|전공 검증 → 임시 지휘 → 임관|
|M05|전설의 지휘관|256×256|120~160분|교두보 → 생산시설 → 최종 작전 → 철수|

원문 전체 목표는 약 8~11시간이다. 미션별 합계는 460~640분, 약 7시간 40분~10시간 40분이다.
최소 구간의 차이를 반올림 차이로 기록한다. 실제 플레이 시간으로 확정한다.
맵 크기는 목표다. 이동 시간과 구역 밀도는 플레이테스트로 검증한다.
일반 난이도를 먼저 제작한다. 대상은 StarCraft: Remastered의 `.scx` UMS다.

## 세계관

시기는 2499년 말~2500년 초다. 베스퍼 VII과 주인공 부대는 창작 설정이다.
M01은 2499년 12월이다. M02는 2499년 12월~2500년 1월이다.
M03은 2500년 1월이다. M04는 1월 말이며 M05는 2월이다.
세부 날짜는 공식 근거 확인 전까지 잠정값으로 유지한다.
소위 임관을 기본안으로 한다. 대위급 권한은 임시 보직으로 설명한다.
연합을 일방적으로 찬양하거나 부정하지 않는다. 결말은 연합 붕괴 후 병력 생존과 재편성으로 연결한다.

## 성장

|단계|체력|공격력|방어력|
|---|---:|---:|---:|
|일반|40|6|0|
|숙련|55|7|1|
|베테랑|75|9|2|
|정예|100|12|3|
|전설|130|14|4|

모든 수치는 임시값이다. 장비 성장과 작전 경험을 구분한다.
반복 처치로 최고 단계에 도달하지 않는다. 포위와 중장갑 적의 위협을 유지한다.
소총, 전투복, 통신장치, 의료 모듈, 폭약 장비를 사용한다.

## 스킬·경제·전공

Q는 18초 쿨타임과 최대 6초 지속시간을 가진다. 이동하면 해제한다.
W는 3초 시전 후 25 체력을 회복한다. 완료할 때 키트 1개와 40초 쿨타임을 적용한다.
E는 30초 쿨타임과 4초 지속시간을 가진다. 공격 주기 변경은 기술 검증 대상이다.
R은 3초 설치와 60초 쿨타임을 가진다. 폭약 1개를 사용한다.
R은 설치, 안전거리 확보, 폭발을 구분한다. 자신과 아군의 피해 가능성을 유지한다.
마나를 사용하지 않는다. 입력과 자원 처리는 `SKILL_DESIGN.md`를 따른다.
군수자재, 특수부품, 의료 키트, 폭약을 구분한다. 선택 보급품 없이도 필수 목표를 진행할 수 있어야 한다.
필수 개량과 폭약에는 대체 보급 경로를 둔다. 획득 ID와 전공 ID는 한 번만 기록한다.
전공은 전투, 작전, 지휘 기록으로 구분한다. M04 필수 진행은 선택 전공량에 의존하지 않는다.

## 연출과 상태

M01 프롤로그 목표는 8~12분이다. 정상 근무, 이상 징후, 최초 접전, 전면 공격을 연결한다.
철수 실패, 수송선 추락, 탄약고 폭발, 의식 회복을 연결한다.
IDLE, PREPARED, RUNNING, COMPLETED, SKIPPED, RECOVERED 상태를 사용한다.
카메라와 조작 제한에는 소유자를 둔다. 스킵 후 필수 시설과 플래그를 확정한다.
환경음, 전장음, 무전, 강조음을 구분한다. 중요한 무전과 경쟁하는 효과음을 줄인다.

## 데이터·아키텍처·검증

논리 상태는 hero, inventory, records, command, metadata와 버전·미션·체크포인트를 포함한다.
미션 간 Death Counter 자동 전달을 가정하지 않는다. EUD 기본 저장을 전제로 하지 않는다.
고정 시작 A, 수동 코드 B, 외부 런처 C를 비교한다. B의 입력·복원 검증 전까지 A를 유지한다.
체크포인트는 유효한 세계를 재구성한다. 모든 전투 상태의 정확한 복제는 요구하지 않는다.
GameState, MissionDirector, CinematicDirector, CombatSystem, EconomySystem을 분리한다.
전공, 지휘, 데이터 전달, 진단 모듈을 분리한다. 상태 변경 책임자는 하나로 제한한다.
구역별 활성화, 유닛 상한, 스캔 예산을 적용한다. 대규모 성능은 실게임에서 측정한다.
외부 자산의 출처와 라이선스를 기록한다.
P0는 빌드·실행, 입력, 쿨타임·중단, 능력치, 카메라·스킵, 저장, 체크포인트다.
P1은 폭약 범위 피해, 전공, HUD, 생성·정리, 지휘 전환, 오디오다.
P2는 상세 보상, 동적 UI, 분기 대사, 추가 난이도, 런처다.
진행 불가, 연출 중복, 필수 보급 소실, 중복 소비, 복구 실패, 맵 실행 실패는 출시 시 0건이어야 한다.
모든 필수 실게임 항목을 검증한 후 Astra가 제작 경로를 확정한다.
