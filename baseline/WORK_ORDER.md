# STARCRAFT: THE LAST MARINE
## 통합 개발 작업 지시서 V1.0

프로젝트: STARCRAFT: THE LAST MARINE  
대상 게임: StarCraft: Remastered / Brood War  
작업 범위: 5개 대형 시네마틱 스토리 미션  
기준 문서: 전체 설계도 V1.0  
개발 방식: AI 주도 · 단계별 검증 · Git 버전 관리  
현재 단계: Phase 1 시작 전

# 1. 전체 작업 원칙

본 프로젝트의 목표는 스타크래프트 1 엔진 안에서 고품질 시네마틱 캠페인을 제작하는 것이다.

일반적인 UMS 형식의 단순한 목표 수행과 이벤트 나열을 지양한다.

연출은 실제 전장 행동, 유닛 동선, 카메라, 음향, 상황 변화로 구성한다.

플레이어의 조작권과 전술적 선택을 유지한다.

## 1.1 필수 요구사항

1. 5개 대형 스토리 미션을 제작한다.
2. M01에서 실시간 기지 붕괴를 구현한다.
3. M01~M03에서 해병 단독 생존을 유지한다.
4. 장비 성장과 쿨타임 기반 전술 스킬을 구현한다.
5. 보급품 수집과 군수시설 복구를 구현한다.
6. 플레이어의 주요 전공을 기록한다.
7. M04에서 연합군 복귀와 전공 심사를 구현한다.
8. M04~M05에서 부대 지휘 기능을 단계적으로 제공한다.
9. M05의 결말을 테란 연합 붕괴 사건과 연결한다.
10. 모든 필수 시스템의 실제 게임 실행을 검증한다.

## 1.2 작업 금지사항

- 확인되지 않은 API를 존재하는 것처럼 사용하지 않는다.
- 빌드 성공을 실제 플레이 성공으로 보고하지 않는다.
- 테스트하지 않은 기능을 PASS로 기록하지 않는다.
- 기본 Death Counter가 다른 맵에 자동 전달된다고 가정하지 않는다.
- EUD 맵의 기본 게임 저장 기능을 전제로 개발하지 않는다.
- 승인 없이 프로젝트의 핵심 게임플레이를 변경하지 않는다.
- 연출만을 위해 플레이어의 조작권을 장시간 제한하지 않는다.
- 저그의 위협성을 없애는 과도한 영웅 능력을 추가하지 않는다.
- 필수 목표를 완료할 수 없는 자원 고갈 상황을 방치하지 않는다.

## 1.3 모델 역할 분담

| 단계 | 담당 | 주요 역할 |
|---|---|---|
| Phase 1 | GPT-6.1 Sol | 상세 기획, 기술 조사, PoC |
| Phase 2 | GPT-6 Astra | 핵심 기술 설계, 위험 분석, 설계 승인 |
| Phase 3 | GPT-6.1 Sol | 전체 캠페인 구현 |
| Phase 4 | GPT-6.1 Sol | 통합 QA, 밸런스, 최종 완성 |

모델명은 계획상의 담당 역할을 의미한다.

실제 모델 선택 가능 여부와 개발 도구 접근 권한은 작업 시작 시 확인한다.

# 3. Phase 1 — GPT-6.1 Sol
## 상세 기획 및 핵심 기술 증명

Phase 1의 목표는 설계 문서를 확장하고 실제 구현 가능한 기능을 확인하는 것이다.

이 단계에서 전체 캠페인을 제작하지 않는다.

핵심 기능을 재현하는 작은 실험과 시네마틱 프로토타입을 먼저 제작한다.

## WO-01 — 개발 환경 조사

### 작업

1. StarCraft: Remastered의 대상 버전을 확인한다.
2. ScmDraft 2의 기능과 제약을 조사한다.
3. scmJS와 TrigScript의 설치 및 빌드 절차를 확인한다.
4. eudplib, euddraft, epScript를 대체 후보로 조사한다.
5. 필요한 도구의 라이선스를 확인한다.
6. 각 도구의 현재 지원 기능과 제한사항을 기록한다.

### 산출물

- TOOLCHAIN_RESEARCH.md
- API_COMPATIBILITY.md
- VERSION_MATRIX.md
- RISK_REGISTER.md

### 완료 조건

실제 사용 가능한 제작 도구를 확보한다.

최소 1개의 테스트 맵을 빌드한다.

게임 실행 여부를 별도로 기록한다.

실행하지 못했다면 BLOCKED로 보고한다.

## WO-05 — 90초 기지 붕괴 PoC

### 목적

전체 시네마틱 개발에 필요한 핵심 연출 기술을 증명한다.

### 장면 순서

| 시점 | 이벤트 |
|---|---|
| 0~15초 | 기지 정상 근무 |
| 15~30초 | 외곽 초소의 교신 단절 |
| 30~45초 | 저그 접근 및 첫 교전 |
| 45~65초 | 방어선 돌파 |
| 65~80초 | 후퇴 및 통신시설 파괴 |
| 80~90초 | 폭발과 다음 장면 전환 |

### 필수 구현

- 아군의 자동 이동.
- 적군의 접근 및 교전.
- 구조물 파괴.
- 무전 메시지.
- 카메라 이동.
- 폭발음.
- 장면 스킵.
- 종료 후 상태 복구.

### 테스트

1. 정상 진행을 확인한다.
2. 장면을 시작하자마자 건너뛴다.
3. 중간 단계에서 건너뛴다.
4. 중요 NPC가 사망한 상태를 시험한다.
5. 플레이어가 경로에서 벗어나는 상황을 시험한다.
6. 같은 이벤트가 중복 실행되지 않는지 확인한다.
7. 최종 상태가 정상인지 확인한다.

### 완료 조건

90초 시퀀스가 실제 게임에서 정상 종료된다.

스킵과 비정상 상황이 진행 불가로 이어지지 않는다.

- 전쟁의 진행 과정이 이해된다.
- 연출이 자연스럽게 연결된다.
- 주요 시네마틱을 건너뛸 수 있다.
- 주인공의 생존 상태가 일관된다.
- 후속 생존 구간으로 정상 진입한다.

### 완료 조건

핵심 테스트에서 진행 불가 오류가 없다.

연출의 개선점이 플레이테스트 보고서에 기록되어 있다.

# 5. Phase 2 — GPT-6 Astra
## 전체 설계 심사 및 기술 기준선 확정

이 단계는 프로젝트의 핵심 설계를 확정하는 단계다.

Astra의 주요 역할은 기존 기획의 위험을 찾고, 실제 개발 가능한 구조로 재설계하는 것이다.

## WO-08 — 종합 설계 심사

### 입력 자료

- 전체 설계도 V1.0.
- Phase 1 전체 산출물.
- 모든 PoC의 소스와 결과.
- API 호환성 자료.
- 문제 및 실패 기록.
- 실제 플레이 영상 또는 재현 가능한 테스트 절차.
- 기술적 제한사항.
- 위험 목록.

### 필수 분석 항목

1. 전체 스토리와 원작 세계관의 정합성.
2. 미션별 플레이 구조와 성장 페이싱.
3. 시네마틱 제어 방식.
4. 이벤트 스케줄링 및 상태 관리.
5. 전술 스킬의 구현 방식.
6. 장비 업그레이드와 실제 능력치 변경.
7. 보급품 경제와 진행 불가 위험.
8. 미션 간 데이터 전달 방식.
9. 전공 기록의 정확성.
10. 단독 조작에서 부대 지휘로의 전환.
11. 대규모 전투의 성능.
12. 테스트 자동화와 실게임 검증 체계.

### 핵심 지시

검증된 기능과 미검증 기능을 구분한다.

구현이 불가능하거나 불안정한 기능에는 대안을 제시한다.

프로젝트의 핵심 경험을 유지하는 대안을 우선한다.

기존 설계가 부적절하면 근거를 제시하고 수정한다.

### 확정 대상

1. 승인된 설계서를 읽는다.
2. 해당 작업 범위를 확인한다.

4. 필요한 모듈만 수정한다.

6. 실제 게임 검증이 필요한 항목을 구분한다.

8. 결과를 커밋한다.
9. 최종 작업 보고서를 작성한다.

### 설계 변경 통제

다음 상황에서는 작업을 중단하고 설계를 재검토한다.

- 기존 아키텍처로 필수 기능을 구현할 수 없다.
- 사용 중인 API가 지원되지 않는다.
- 제작 도구 변경이 필요하다.
- 저장 방식 변경이 요구된다.
- 핵심 게임플레이가 변경된다.
- 성능 문제로 미션 규모를 조정해야 한다.

사소한 버그 수정은 별도 설계 심사 없이 진행할 수 있다.

기존 설계를 무조건 승인하지 않는다.

문제가 있는 구조는 구체적으로 수정한다.

기술적 근거가 부족한 기능은 미검증으로 분류한다.

최종적으로 개발자가 추가 해석 없이 구현할 수 있는 상세 설계서를 작성한다.

Sol에게 전달할 작업 계약과 검증 기준을 확정한다.

승인 판정은 GO, CONDITIONAL GO, REWORK, NO-GO 중 하나로 작성한다.

# 14. 프로젝트의 최종 개발 원칙

이 프로젝트는 화려한 연출만을 목적으로 하지 않는다.

플레이어의 행동, 게임 시스템, 스토리가 자연스럽게 연결되어야 한다.

초반의 고립과 생존은 실제로 어렵게 느껴져야 한다.

장비와 스킬의 성장은 전투 방식에 영향을 줘야 한다.

전공 인정은 플레이어가 수행한 작전을 근거로 해야 한다.

후반의 지휘관 승격은 새로운 게임플레이로 이어져야 한다.

모든 핵심 시스템은 실제 스타크래프트에서 실행되어야 한다.

**기술 검증 → Astra 설계 승인 → 단계별 구현 → 실게임 검증**의 순서를 유지한다.

문서 종료.
