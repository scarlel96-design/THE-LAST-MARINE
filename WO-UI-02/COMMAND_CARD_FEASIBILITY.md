# WO-UI-02 명령창 구현 경로

현재 판정: **PARTIAL**. 현재 소스를 빌드했다. 실게임 맵 선택 입력은 반영되지 않았다.

## 실제 관찰

1.23.10.13515에서 영웅 해병의 기본 명령과 추가 버튼 두 개가 표시됐다.
현재 화면 증거는 LIVE_UI_SCREENSHOTS/02, 03이다.
W 진단 버튼의 툴팁은 `이동 지점 [W]`였다.
이 문자열은 입력 경로를 분리하기 위한 임시 표식이다.
클릭과 W 반복 입력 이후에도 체력 30/40, 자원 3/2가 유지됐다.
해당 실행에서 치료 시작은 관찰되지 않았다.
정상 작동과 최종 한국어 툴팁은 미검증이다.

## 배치와 입력

|위치|명령|처리|
|---|---|---|
|1~5|이동, 정지, 공격, 순찰, 위치 사수|원래 버튼 레코드 보존|
|7|전투 자극제|원래 버튼 레코드 보존|
|8|Q 방어 자세|전용 명령 토큰 92 감지|
|9|W 긴급 지혈|전용 명령 토큰 93 감지|

영웅 타입 20의 버튼셋 포인터만 교체한다.
일반 해병 타입 0의 버튼셋 포인터는 변경하지 않는다.
Q/W는 네이티브 버튼의 생산 대기열 입력을 감지한다.
F7/F8은 소비·쿨타임 로직의 진단 입력이다.
F7/F8 검사는 마우스 클릭 또는 Q/W 단축키 검증을 대신하지 않는다.
현재 버튼의 사용 가능 표시는 Always 조건을 사용한다.
잠금·쿨타임 요청 차단은 기존 스킬 로직에서 처리한다.
버튼 자체의 비활성 표현은 미완성이다.
선택 전환, 중복 입력, 기본 명령, 전투 자극제는 실게임 회귀 항목이다.

## 중단 후 소스 수정

기존 요구 조건 인덱스 572는 파일 전체의 워드 번호였다.
도구 소스는 0x46C바이트 헤더 이후를 유닛 요구 조건의 시작으로 사용한다.
상대 워드 번호는 `(572 * 2 - 0x46C) / 2 = 6`이다.
유닛 요구 조건 영역은 1096바이트다.
572는 이 영역의 워드 범위를 벗어난다.
현재 소스는 6을 사용한다.
현재 소스는 0x514184의 하위 워드가 0xFFFF인지 먼저 검사한다.
조건이 다르면 추가 버튼셋을 설치하지 않는다.
현재 소스의 상태·대기열 검사 36개는 통과했다. 클릭 동작 개선 여부는 NOT RUN이다.
다른 입력 문제의 존재 여부도 아직 확정하지 않았다.

## 제작 사례와 도구 근거

제작자 사례는 비생산 유닛의 생산 대기열을 명령 입력으로 사용한다.
제작 사례만으로 현재 클라이언트 호환성을 확정하지 않는다.
[SkywinDragoon 제작자 사례](https://staredit.net/topic/18083/)

버튼 레코드, 원래 버튼, 요구 조건 파일 형식은 EUD Editor 3 소스에서 읽었다.
클라이언트에 해당 편집기의 DLL을 설치하거나 주입하지 않았다.
[ExtraDatFiles](https://github.com/Buizz/EUD-Editor-3/blob/8994429745a16992753a81cd3301d90941b3e458/EUD%20Editor%203/Class/ExtraData/ExtraDatFiles.vb)
[WriteReqFile](https://github.com/Buizz/EUD-Editor-3/blob/8994429745a16992753a81cd3301d90941b3e458/EUD%20Editor%203/Class/BulidData/WriteReqFile.vb)

기존 TrigScript는 그대로 보존한다.
시험 빌더만 마스크 조건과 대기열 필드 네 개를 추가한다.
이 어댑터는 정식 런타임에 병합하지 않았다.
